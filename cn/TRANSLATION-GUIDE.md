# AIMLInterviews 简体中文翻译指南

本文档规定简体中文版的语气、术语和质量要求。目标是写出中国大陆 AI/ML 工程和研究社区中自然、准确的技术中文，而不是逐词翻译英文。

## 语气与表达

- 面向 AI/ML 工程师、研究人员、研究生和技术面试候选人。
- 语气专业、清晰、直接；优先使用自然的中文句式。
- 保留原文中示例、限制、警告和建议的作用，不机械照搬英文语序。
- 使用中国大陆技术文档和工程社区中的常见术语，不创造生僻译名。

## 术语规则

- AI、ML、LLM、RAG、NLP、CV、API、MCP 等常用缩写保留英文。
- Python、PyTorch、NumPy、BERT、GPT、Apple、Meta 等语言、库、模型、产品和公司名称保留原文。
- 代码、命令、变量、函数、文件路径、公式、URL、版本号和复杂度表达式不得翻译。
- generative AI 优先写作“生成式 AI”；agentic AI 优先写作“智能体 AI”。
- machine learning 写作“机器学习”；deep learning 写作“深度学习”；foundation model 写作“基础模型”。
- fine-tuning 写作“微调”；inference 写作“推理”；deployment 写作“部署”；evaluation 写作“评估”。
- embedding、token、prompt、benchmark 等术语可保留英文，首次出现时按上下文给出简短中文说明。

## Markdown 与链接

- 保留标题层级、表格、列表、引用、HTML anchor、代码块和行内代码。
- 链接文字可以翻译，但外部 URL 必须逐字保持不变。
- 当对应中文页面存在时，内部文档链接应指向中文版；代码、notebook、图片和其他未本地化资源继续指向可解析的原路径。
- 不翻译 MIT License 正文；英文许可证是法律依据。

## 每页质量检查

- 内容能否脱离英文原文独立、自然地阅读？
- 是否保留了所有技术事实、数字、限制、链接和警告？
- 技术术语是否前后一致？
- 代码块、行内代码、表格、公式、anchor 和链接是否完整？
- 是否避免了逐词翻译、欧化句式和不常见的生造术语？

## 同步政策

英文版是内容来源。英文 `README.md` 或 `src/**/*.md` 更新后，自动化会生成中文更新并通过 pull request 提交审核。自动生成的翻译必须通过结构与链接检查，合并前仍需人工确认语言质量。
